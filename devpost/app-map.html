A small guide to the working app

Conversation Goal Companion

Talk or type about real life. The app keeps the conversation, turns clear goal details into editable steps, and carries the dashboard into later chats.

1 · ConversationTyped or live voice turns appear in the current chat.
2 · OrganizeWhen you choose to save, the server asks Gemini for a summary and goal updates.
3 · Check evidenceThe organizer merges goals and only accepts task completion with clear transcript evidence.
4 · See progressThe dashboard shows ordered steps; browser storage keeps chats and plans on this device.

Follow one action in the code

This is a reference route through the saved-chat organizer. The map points to current source symbols; it does not claim that a guided editor tour has happened.

  1. src/components/ChatShell.tsx, search for finishConversation. This sends the transcript and existing plans to /api/organize, then saves the summary and returned dashboard plans in app state.
  2. src/app/api/organize/route.ts, inspect mergePlan and mergePlans. These match updates to existing goals, preserve open tasks, and require transcript evidence before accepting a new completion.
  3. src/lib/storage.ts, inspect saveAppState; then src/lib/context.ts, inspect buildDashboardContext and buildPriorChatContext. The first keeps the plan in this browser; the latter prepares dashboard and selected prior-chat context for later conversations.

To change this, start here

  • Change how a conversation updates goals or task completion: src/app/api/organize/route.ts, mergePlan.
  • Change what a new chat remembers: src/lib/context.ts, buildPriorChatContext and buildDashboardContext.
  • Change what the person can edit on the dashboard: src/components/ChatShell.tsx, task handlers and LifeDashboard.

A practice to reuse

Turn a broad promise into a visible check. Here, “a later chat remembers the goal” became an observable check: start a separate chat, ask about the saved goal, and compare the reply with the dashboard. That exposed missing continuity and gave the code a concrete target in buildDashboardContext and buildPriorChatContext.

Open and run the project

  1. Use Node.js 22 or newer, install dependencies with npm install, and make a private .env.local from the variable names in .env.example.
  2. Start it with npm run dev, then open http://localhost:3000. Keep API keys and passwords out of the repository.
